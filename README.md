# Performance Optimizer для Lords and Villeins

Версия: **1.3.0**. Unity Mod Manager + Harmony, .NET Framework 4.7.2.

Цель — уменьшать лишние временные выделения памяти в игровых методах без пропуска симуляционных обновлений и без искусственного «ускорения» через замедление жителей. Это не FPS-анализатор.

## Что реализовано

### Пулы временных коллекций

1. **`AIAgent.UpdateOutOfRangeNearbyAgents`** — игровой проход по наборам соседей в бою сохранён, временные два `HashSet` заменяются переиспользуемым списком для удаления элементов. Патч отключается, если обнаружен FPSBoost.
2. **`PathfindingManager.LateUpdate`** — временный список `FindPathRequest` переиспользуется между вызовами. Патч отключается при обнаружении FPSBoost.
3. **`AIManager.TriggerCombatPositions`** — временные списки боевого события переиспользуются.
4. **`AIAgent.FindNewFightingTarget`** — список кандидатов на боевую цель переиспользуется, сортировка и логика выбора остаются оригинальными.

### Исправления безопасности в 1.3.0

- Пулы для path batch, combat positions и target selection стали **reentrancy-safe**: вложенный вызов получает отдельный буфер своего уровня, а не перезаписывает коллекцию внешнего вызова.
- Очистка буферов выполняется Harmony Finalizer, то есть и при нормальном выходе, и при исключении.
- Транспайлеры теперь сначала проверяют точное количество ожидаемых конструкторов. Если IL отличается от ожидаемого, метод остаётся нетронутым целиком, а в лог записывается причина. Это предотвращает частичное переписывание метода после обновления игры.
- Временные буферы создаются лениво и переиспользуются на потоке.

### Экономия ресурсов в фоне

Когда окно игры не в фокусе, мод может ограничить частоту кадров (по умолчанию 15 FPS). Это экономит ресурсы только в фоне и не снижает частоту симуляции при активной игре.

## Совместимость с FPSBoost 1.2.0

Рекомендуемый режим на данном этапе — **оставить FPSBoost включённым**. В переданном архиве FPSBoost есть только DLL, `Info.json` и `Settings.xml`, исходников C# нет. Поэтому нельзя достоверно переписать или заменить его уникальные алгоритмы.

При обнаружении FPSBoost Performance Optimizer пропускает два пересекающихся патча:
- `AIAgent.UpdateOutOfRangeNearbyAgents`;
- `PathfindingManager.LateUpdate`.

Пулы `AIManager.TriggerCombatPositions` и `AIAgent.FindNewFightingTarget` остаются активны. Это предварительная совместимость по известным точкам пересечения, а не гарантия отсутствия конфликтов со всеми версиями и модами. Если FPSBoost установлен в нестандартной папке, проверьте строку обнаружения в `Main.IsFpsBoostInstalled()`.

Настройки FPSBoost из присланного `Settings.xml`:
- `optimizeReactionTime=true`;
- `parallelComputing=true`;
- `animalsLeave=true`;
- `animalsOnlyEatFromFeeders=true`;
- `noSpreadOfTrees=true`;
- `autoNightSpeed=true`.

В DLL также найдены имена Harmony-патчей `GameManager_AfterLoadingFinished_Patch`, `PathfindingManager_LateUpdate_Patch`, `AnimalManager_GetMaxHerdsOnMapByMapSize_Patch`, `WorldManager_SpawnVegetationFromSpreading_Patch`, `ACAnimalHerbivoreEat_GetTreesForEating_Patch`, `ACAnimalHerbivoreEat_GetCropsForEating_Patch`, `AIAgent_PickGoal_Patch` и патчи перестроения pathfinding grid. Наличие имени подтверждает точку вмешательства, но не раскрывает полностью алгоритм патча.

Эти функции не дублируются и не отключаются Performance Optimizer.

## Настройки Performance Optimizer

- Пулы боевых коллекций — включены по умолчанию.
- Оптимизация очистки боевых соседей и пул path batch — используются только если FPSBoost не найден.
- Ограничение FPS в фоне — включено по умолчанию.
- Ручные лимиты поиска путей и GOAP — выключены/нейтральны по умолчанию. Снижение лимитов может замедлить реакцию жителей, поэтому мод не меняет их автоматически.

## Сборка

1. Закройте игру.
2. Распакуйте архив.
3. Откройте `PerformanceTuner.csproj` в Visual Studio 2019/2022.
4. Проверьте `GameDir.props`: `GameDir` должен указывать на папку Lords and Villeins.
5. Выберите `Release` и выполните сборку.
6. Если каталог `Mods` существует, MSBuild скопирует DLL и `Info.json` в `Mods/PerformanceTuner`.

Целевая платформа: .NET Framework 4.7.2. Ссылки на игровые, Unity, UMM и Harmony сборки берутся из установленной игры.

## Честный статус проверки

- ZIP проекта структурно проверяется при упаковке.
- FPSBoost RAR проверен: содержит DLL, кэш, `Info.json`, `Settings.xml`, но не содержит исходного C#.
- Исходный код игры (`Assembly-CSharp.dll`) в последней загрузке пользователя не приложен, поэтому новые игровые методы за пределами уже исследованных точек не добавлялись.
- В текущей среде нет `dotnet`, `msbuild`, `csc`, `mcs` или Mono и нет запущенной игры. Поэтому **DLL 1.3.0 не собран и игровой тест не выполнен**.
- Процент прироста FPS не обещается. Пулы уменьшают временные аллокации в перечисленных методах, но реальный эффект зависит от размера поселения и частоты вызовов.

Перед релизом необходимо собрать проект и проверить: загрузку сохранения, бой, выбор цели, массовую обработку боевых позиций, поиск путей, паузу/возобновление, выгрузку мода и совместную работу с FPSBoost.
